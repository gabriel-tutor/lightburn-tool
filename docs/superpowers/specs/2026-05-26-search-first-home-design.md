# Search-First Home — design

**Date:** 2026-05-26
**Status:** Approved
**Driver:** Drag-and-drop a PDF was a tech-driven simplification that doesn't
match production reality. The order is upstream data (Supabase/Airtable);
each line item references its **own** design PDF. Production operators
receive an order number — not a file — from the order system. The home
screen should be built around order lookup, not file dragging.

## Goal

Operator opens the app → types an order number (or picks one from a list)
→ sees the order summary → engraves each item. The PDF drag-drop interaction
is replaced entirely.

Interactions:
- Operator types order number → presses Enter OR clicks Open → app calls
  `repo.get(order_number)`. Found → navigate to order view. Not found →
  inline label "Order not found." (red, beneath input). No modal dialog —
  zero-friction recovery.
- Operator clicks any recent-orders card → navigate to order view.
- Search input gets `setFocus()` on home-screen show so the operator can
  just start typing.

## Architecture changes

### Port — unchanged

`OrderRepository.get(order_number)` and `list_all()` already cover the
home screen's needs.

### Adapter — directory-based

`JsonOrderRepository(orders_dir: Path, *, seed_dir: Path | None = None)`:

- `json_path = orders_dir / "orders.json"`
- On first run: if `orders_dir` doesn't exist and `seed_dir` is given, the
  entire `seed_dir` is **copied recursively** to `orders_dir`. (Both
  orders.json and the design PDFs land in place.)
- `pdf_path` in items is resolved relative to `orders_dir` (or kept absolute
  if absolute). The resolved path is set on the `OrderItem` so callers
  don't need to know about resolution.

### `AppPaths` — orders_dir replaces orders_json_path

```python
@dataclass(frozen=True, slots=True)
class AppPaths:
    db_path: Path
    temp_dir: Path
    orders_dir: Path | None = None
```

### HomeView — full rewrite

```python
class HomeView(QWidget):
    order_searched = Signal(str)        # "305-6737580-7658721"
    order_selected = Signal(object)     # carries an Order
    open_admin = Signal()
    open_audit = Signal()

    def __init__(self, repo: OrderRepository) -> None: ...
    def refresh_recent(self) -> None: ...
    def show_not_found(self, order_number: str) -> None: ...
```

- `QLineEdit` for the order number, `QPushButton "Open"` to submit
- `QListWidget` (or stacked `QFrame`s) for recent orders
- Inline `QLabel#searchError` (hidden by default) for "Order not found"
- Header (Flanacom logo + Engraver subtitle) preserved
- Footer (Admin, Audit) preserved

### MainWindow routing

Drop the drag-drop wiring (`home.pdf_chosen`, `_on_pdf_chosen`,
`_maybe_route_to_order`). Wire:

- `home.order_searched.connect(_on_order_searched)`
- `home.order_selected.connect(_on_order_selected)`

`_on_order_searched(order_number)`:
```python
def _on_order_searched(self, order_number: str) -> None:
    if not order_number or self.deps.orders is None:
        return
    order = self.deps.orders.get(order_number)
    if order is None:
        self.home.show_not_found(order_number)
        return
    self._open_order(order)
```

`_on_order_selected(order)` and `_open_order(order)` populate the order
view and switch to it (refactored from the old `_maybe_route_to_order`).

The drop-zone widget (`src/lbb/ui/widgets/drop_zone.py`) and its tests stay
in the tree as dormant code — easy to bring back if "ad-hoc engraving"
becomes a real need later.

### Packaging

`packaging/lbb.spec` updated to include each seed-orders file via `datas`
(QSS is bundled the same way — same pattern):

```python
(str(ASSETS / "seed-orders" / "orders.json"), "lbb/ui/assets/seed-orders"),
(str(ASSETS / "seed-orders" / "305-A-john.pdf"), "lbb/ui/assets/seed-orders"),
# … one entry per file
```

## Edge cases

| Situation | Behaviour |
|---|---|
| Empty search input + Open clicked | No-op (button disabled when input is empty) |
| Order number not in repo | Inline "Order not found." message (red); search input keeps focus |
| Item references missing PDF | `_continue_with_profile` surfaces "Couldn't open PDF" critical dialog (existing pdfium error path) |
| `~/.flanacom-tool/orders/` already exists from a prior version | Not re-seeded; operator's file wins (per existing first-run policy) |
| `orders.json` malformed | Logged to stderr; `get` returns None for every order; "Order not found" shown on search |
| No orders in repo | Recent-orders list shows empty-state copy: "No orders yet — add some via Supabase or edit ~/.flanacom-tool/orders/orders.json" |
| Same order number searched twice | Second search re-fetches and re-routes — idempotent |

## Non-goals

- Ad-hoc engraving (one-off PDFs that aren't part of any order). Operator
  can use LightBurn directly for that, or we can add an "Engrave a one-off…"
  link in a follow-up.
- Search filtering / fuzzy match / autocomplete on the order number input.
  Exact match against `repo.get()` for now.
- Pagination of the recent-orders list. We expect <50 orders for the demo.
- Real Supabase integration. Port is ready; adapter swap is a future task.
- Per-item PDF re-rendering or generation at runtime — the seed ships
  pre-rendered designs.
